## Actual

Verificado en `origin/develop@54bbdcd7`:

1. `admin_decide_courier` (`supabase/migrations/20260924013700_rpc_admin_v1.sql:34`) solo decide desde `pending`
   (regla D03, `:70-73`); con cualquier otro estado lanza `INVALID_STATE_TRANSITION`.
2. `admin_suspend_courier` (mismo archivo, `:104`; redefinida en
   `20260927120000_cc012_incidents_contract.sql`) pasa a `suspended` desde cualquier estado distinto de `suspended`,
   pone `available = false`, `deactivated_at = now()` y retira las ofertas `pending`.
3. No hay ninguna RPC que vuelva a `approved` desde `suspended` o `rejected`. La RLS niega el `update` directo de
   `couriers.status` (master plan §7).
4. UI: `src/features/admin/components/applicant-detail-view.tsx:313-328` muestra «Reactivar repartidor» (suspendido) y
   «Reconsiderar aprobación» (rechazado), y los dos llaman `decideCourierAction` con `approved`. La RPC responde
   `INVALID_STATE_TRANSITION`.
5. `decideCourierAction` (`src/features/admin/actions.ts:250-255`) no mapea `INVALID_STATE_TRANSITION` y devuelve
   `INTERNAL_ERROR`: el admin ve «Ocurrió un inconveniente inesperado» (QA staging 2026-10-20).

## Propuesto

```sql
public.admin_reinstate_courier(p_courier_id uuid, p_reason text) returns jsonb
-- security definer, set search_path = public, pg_temp
-- revoke all from public, anon, authenticated; grant execute to authenticated
```

Salida:

```json
{ "courierId": "uuid", "previousStatus": "suspended|rejected", "status": "approved", "idempotent": false }
```

Validaciones, en este orden:

1. `perform app_private.assert_admin_aal2()` (sin sesión, sin rol admin o sin MFA: mismos códigos que el resto de las
   RPC admin).
2. `p_reason` nulo o vacío tras `trim` → `REASON_REQUIRED`; más de 500 caracteres → `VALIDATION_ERROR`.
3. `select status, vehicle_type from public.couriers where profile_id = p_courier_id for update`. Sin fila →
   `NOT_FOUND`.
4. Según el estado bloqueado:
   - `approved` → devuelve `idempotent: true` y `previousStatus: 'approved'`, sin `update` ni auditoría (doble clic o
     reintento);
   - `pending` → `INVALID_STATE_TRANSITION` (la primera decisión sigue siendo `admin_decide_courier`, D03 intacta);
   - `suspended` o `rejected` con `vehicle_type is null` (onboarding incompleto) → `INVALID_STATE_TRANSITION`.
5. `update public.couriers set status = 'approved', decided_at = now(), decided_by = auth.uid(), deactivated_at = null`.
   `available` **no** cambia: queda en `false` y el repartidor la vuelve a activar con `set_availability`.
6. `audit_log`: `action = 'admin_reinstate_courier'`, `target_type = 'courier'`, `before = {status}`,
   `after = {status: 'approved', reason}`. Sin datos de documentos ni de contacto.

No toca documentos, `doc_level`, `dni_hmac`, consentimientos ni ofertas. Las ofertas retiradas por la suspensión no se
restauran.

## Seguridad y permisos

- **RLS:** sin cambios. `couriers.status` sigue sin `update` directo para clientes.
- **Grants:** `revoke all on function public.admin_reinstate_courier(uuid, text) from public, anon, authenticated;`
  `grant execute … to authenticated;`. La autorización real la hace `assert_admin_aal2` adentro.
- **`security definer`** con `set search_path = public, pg_temp`. Sin helpers `app_private` nuevos.
- **Acceso directo frente a RPC:** el `update` directo de `couriers.status` sigue rechazado; el pgTAP lo reprueba.
- **Server Action:** cliente de sesión con AAL2 (`requireAdminAal2`), nunca `createAdminClient` (mismo patrón que
  `decideCourierAction`, PR106-H04).

## Concurrencia e idempotencia

- **Locks:** solo `couriers FOR UPDATE` sobre la fila del repartidor, el mismo primer lock que `admin_suspend_courier`,
  `admin_decide_courier` y las RPC del repartidor. Sin deadlocks nuevos.
- **Reintentos:** sobre un `approved` devuelve `idempotent: true` sin auditoría duplicada.
- **Carreras:**
  - reactivar y suspender a la vez: el lock serializa; gana el orden de commit y el estado final es el de la última
    operación, con una fila de auditoría por cada una que cambió algo;
  - dos admins reactivan a la vez: la segunda ve `approved` y devuelve `idempotent: true`;
  - `submit_offer` verifica el estado en cada llamada (master plan §6.3): antes del commit sigue rechazando, después
    acepta si el repartidor activó `available`.
- **Prueba exigida en la PR de implementación (no en esta PR documental):** suite
  `supabase/tests/integration/cc034_concurrency.mjs` con **dos sesiones PostgreSQL reales e independientes**,
  sincronizadas con locks o barreras deterministas, sin `sleep` ni mocks de la capa de base:
  - **reactivar/reactivar:** exactamente 1 fila de auditoría y la segunda con `idempotent: true`;
  - **reactivar/suspender** en los dos órdenes: sin `40P01`, estado final consistente con el orden de commit;
  - **mutación RED:** quitar temporalmente el `for update` en una copia efímera de la migración tiene que dejar en rojo
    el caso reactivar/reactivar (auditoría duplicada); al restaurar, verde. Esta PR no afirma esa evidencia.

## Compatibilidad, rollout y rollback

- **UI vieja contra el esquema nuevo:** sigue llamando `admin_decide_courier`, que sigue fallando igual; nada empeora.
- **UI nueva contra el esquema viejo:** no se despliega antes de la migración; T-380 empieza cuando CI aplica la
  migración en Develop.
- **Backfill:** ninguno.
- **Rollout:** 1) PR de implementación del CC: migración, contrato, fake, tipos, wrapper, pgTAP y suite de
  concurrencia. 2) T-380: acción, UI y E2E.
- **Rollback (forward-only):** antes de T-380, una migración nueva puede hacer `drop function if exists
  public.admin_reinstate_courier(uuid, text)`. Después de T-380, primero se despliega una UI sin los botones y recién
  después el `drop`. La auditoría y los estados ya cambiados se conservan.

## Decisiones de producto

- «Reactivar» (desde `suspended`) y «Reconsiderar» (desde `rejected`) llevan directo a `approved` con motivo
  obligatorio de hasta 500 caracteres y MFA — Lautaro073, 2026-10-20 (decisión en automático con la opción
  recomendada, `decidir-en-automatico`).
- Solo con el onboarding completo (`vehicle_type is not null`); si no, `INVALID_STATE_TRANSITION` — Lautaro073,
  2026-10-20.
- El repartidor reactivado vuelve con `available = false` y no recupera ofertas retiradas — Lautaro073, 2026-10-20.
- Los documentos y el nivel de documentación no cambian — Lautaro073, 2026-10-20.
