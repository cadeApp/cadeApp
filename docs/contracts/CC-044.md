## Propuesto

```sql
public.admin_list_applicants(
  p_status text,                              -- 'pending' | 'approved' | 'rejected' | 'suspended'
  p_query text default null,                  -- nombre; null o vacío tras btrim = sin búsqueda; máx. 80 caracteres
  p_cursor_created_at timestamptz default null,
  p_cursor_id uuid default null,
  p_direction text default 'next',            -- 'next' | 'prev'
  p_limit integer default null                -- 1..50, por defecto 20
) returns jsonb
```

### Normalización (una sola función para el nombre y el término)

```sql
app_private.search_normalize(p_value text) returns text
-- lower(btrim(regexp_replace(regexp_replace(normalize(p_value, NFD), '[̀-ͯ]', '', 'g'), '\s+', ' ', 'g')))
```

Reglas declaradas: descompone en NFD, quita las marcas diacríticas combinables U+0300–U+036F (tildes, diéresis,
virgulilla de la «ñ», etc.), pasa a minúsculas, colapsa los espacios y recorta. Así «José» = «jose» = «JOSE»,
«Núñez» = «nunez» y «Álvaro» = «alvaro». Letras que no se descomponen (por ejemplo «ø», «ß» o «ł») no se igualan a
otra letra: quedan fuera de las reglas y no generan falsos positivos. `immutable`, `strict`, `parallel safe`.

### Filtro, orden y paginación

- Filas: `couriers c join profiles p on p.id = c.profile_id`, con `c.status = p_status`.
- Búsqueda: si hay término, `strpos(app_private.search_normalize(p.display_name),
  app_private.search_normalize(p_query)) > 0`. Es una subcadena literal: `%`, `_` y `\` del término no son comodines.
  Solo busca por nombre; nunca por teléfono, DNI, patente ni correo.
- El filtro de estado y la búsqueda se aplican **antes** de contar, ordenar y limitar.
- Orden: `p.created_at desc, c.profile_id desc` (el de T-420).
- `p_direction = 'next'`: filas estrictamente después del cursor en ese orden (sin cursor, la primera página).
- `p_direction = 'prev'`: filas estrictamente antes del cursor; se toman las `p_limit` más cercanas y se devuelven en
  el mismo orden descendente. Exige cursor.

### Salida

```json
{
  "items": [{
    "id": "uuid",
    "displayName": "José Pérez",
    "phone": "+5493865000001",
    "vehicleType": "moto | bike | walk | car | null",
    "status": "pending",
    "hasDni": true,
    "docLevel": 1,
    "licenseStatus": "none | submitted | verified | rejected",
    "insuranceStatus": "none | submitted | verified | rejected",
    "createdAt": "2026-11-04T12:00:00.000000Z",
    "submittedAt": "2026-11-04T14:00:00.000000Z | null",
    "documents": { "dniFront": true, "dniBack": true, "selfie": true, "license": true, "insurance": false }
  }],
  "total": 37,
  "nextCursor": { "createdAt": "…", "id": "uuid" } | null,
  "prevCursor": { "createdAt": "…", "id": "uuid" } | null
}
```

- `total`: cantidad exacta de filas con ese estado y esa búsqueda, sin cursor ni límite.
- `nextCursor`: el último ítem, si hay al menos una fila después de él; si no, `null`.
- `prevCursor`: el primer ítem, si hay al menos una fila antes de él; si no, `null` (siempre `null` en la primera
  página).
- `hasDni` es `dni_hmac is not null`; el hash nunca sale. `documents` marca qué tipos tienen un documento vigente
  (`coalesce(is_current, true)`), sin rutas ni estados de Storage.
- Fechas en UTC con el formato de `admin_list_trips`.
- Errores, en este orden: `UNAUTHENTICATED`, `UNAUTHORIZED_ACTOR` y `AAL2_REQUIRED` (de `assert_admin_aal2`); después
  `VALIDATION_ERROR` si el estado no es uno de los cuatro, el cursor está incompleto, la dirección no es `next` ni
  `prev`, `prev` llega sin cursor, el límite no está entre 1 y 50 o el término supera 80 caracteres tras `btrim`.

### Índices

Ninguno nuevo. La cola es de cientos de filas (repartidores de Aguilares); el plan esperado es un recorrido de
`couriers` filtrado por estado y el acceso por clave primaria a `profiles`, con `strpos` sobre esas filas. Un índice
de expresión necesita `pg_trgm` para `strpos`/`like '%…%'` y no se justifica a este volumen. Condición para revisarlo:
más de 5.000 repartidores o p95 de la RPC por encima de 300 ms; entonces, CC con `pg_trgm` y un índice GIN sobre
`app_private.search_normalize(display_name)` (por eso el helper es `immutable`).

## Seguridad y permisos

- **RLS:** no cambia ninguna policy.
- **Grants y revokes:** `revoke all on function public.admin_list_applicants(text, text, timestamptz, uuid, text,
  integer) from public, anon, authenticated; grant execute … to authenticated`. La autorización la hace
  `assert_admin_aal2()` antes de leer nada: un no admin o un admin sin `aal2` no enumera nombres. Es más estricto que
  la RLS actual (`is_admin()` sin `aal2`).
- **`security definer`**, `stable`, `set search_path = public, pg_temp`.
- **Helper interno:** `app_private.search_normalize(text)` es `security invoker`, `immutable`, `strict`,
  `set search_path = pg_catalog, pg_temp`; `revoke all … from public, anon, authenticated`, sin `grant`. Solo la llama
  `admin_list_applicants` (que corre como su dueño). No lee tablas.
- **Acceso directo frente a RPC:** solo lectura; no escribe ni congela campos.
- **Datos que nunca devuelve:** `dni_hmac`, rutas de documentos, CBU o alias, consentimientos, correo.

## Concurrencia e idempotencia

No aplica: lectura `stable`, sin locks ni efectos. Un reintento devuelve la página vigente. Si entre dos páginas entra
o sale una fila, el keyset no repite ni salta filas ya vistas en esa dirección; `total` refleja el estado del momento.

## Decisiones de producto

- La búsqueda por nombre ignora tildes y mayúsculas y se resuelve en PostgreSQL (D01 = C) — Lautaro073, 2026-10-21
  (PR #489).
- Se resuelve con una RPC admin que exige `aal2`, en lugar de una columna normalizada con filtro de PostgREST, para que
  un admin sin MFA no enumere nombres antes de T-408 — Lautaro073, 2026-11-04.
- El contador «N pendientes» es el total del estado con la búsqueda aplicada (ficha T-403) — Lautaro073, 2026-10-21.

## Motivo

T-403 necesita buscar «jose» y encontrar «José», con el contador y la paginación en los dos sentidos sobre el mismo
conjunto. Con PostgREST no se puede normalizar el término en la base ni exigir `aal2` hasta T-408. La RPC resuelve las
dos cosas con una sola normalización para el nombre y el término.
