# CC-018 — Select controlado sin reset espurio a vacío

- **Issue:** #219 (label `contract-change`)
- **Fecha:** 2026-10-02
- **Contrato afectado:** `src/ui/select.tsx`
- **Bloquea:** T-326 (#190, PR #218); transitivamente T-313 y T-314

## Problema

El Select compartido expone una API propia (`Select`, `SelectTrigger`, `SelectValue`, `SelectContent`, `SelectItem`) y maneja estado, apertura y opciones con componentes propios.

Sin embargo también envuelve sus hijos en `@radix-ui/react-select` mediante `SelectPrimitive.Root`. Los `SelectItem` del proyecto son botones propios y no `SelectPrimitive.Item`, por lo que Radix no registra las opciones en su select nativo oculto.

En modo controlado dentro de un formulario, seleccionar un valor real puede producir:

```text
onValueChange('<valor>')
onValueChange('')
```

El segundo callback borra el estado del consumidor. T-326 lo reprodujo con UUIDs de barrio y react-hook-form.

## Contrato propuesto

La API pública existente se conserva.

### Selección

- una selección válida llama `onValueChange` exactamente una vez con el valor elegido;
- no se emite `''` de forma espuria después de una selección válida;
- en modo controlado, la prop `value` es la fuente de verdad;
- en modo no controlado, `defaultValue` y las selecciones posteriores siguen funcionando;
- elegir una opción cierra el listbox.

### Accesibilidad / DOM

Se conserva:
- trigger `button` con `role="combobox"`;
- `aria-expanded`, `aria-controls`, `aria-haspopup="listbox"`;
- contenido con `role="listbox"`;
- items con `role="option"` y `aria-selected`;
- foco y comportamiento de teclado ya existentes.

No debe aparecer un `<select>` nativo operable como sustituto visual.

### Implementación permitida

Se autoriza remover el `SelectPrimitive.Root`/import de `src/ui/select.tsx` si esa es la corrección mínima, dado que el wrapper ya implementa el estado/UI públicos y el Root defectuoso es una implementación interna.

No eliminar `@radix-ui/react-select` de dependencias del proyecto dentro de este CC.

## Tests mínimos

- controlado dentro de `<form>`: seleccionar B registra solo `['b']`, nunca `['b', '']`;
- el padre actualiza `value` y el trigger muestra B;
- no controlado: `defaultValue` y cambio de opción funcionan;
- roles/ARIA y apertura/cierre se conservan;
- la opción seleccionada expone `aria-selected=true`;
- mutación/restauración: reintroducir el reset a `''` o el Root defectuoso deja los tests en rojo.
