# CC-045 — MapPicker: ubicar en el mapa una dirección escrita (Geocoding)

- **Issue:** #615 (label `contract-change`) · **Abre:** Lautaro073 (agente) · **Fecha:** 2026-11-05
- **Contrato afectado:** `src/ui/map.tsx` (`MapPickerProps`, `MapPicker` y helpers exportados nuevos)
- **Tareas bloqueadas:** T-423 (#616)
- **Depende de:** CC-027 (`showMarkerWhenEmpty`), sin cambios sobre él

## Actual

En `src/ui/map.tsx`:
- `MapPickerProps` (`:72-85`) recibe el pin (`value`), el centro del barrio (`defaultZoneCenter`), el GPS opcional
  (`showLocationButton`, `onLocationFound`, `onLocationError`) y `showMarkerWhenEmpty` (CC-027). No hay forma de
  pedirle que busque una dirección.
- El `APIProvider` de `@vis.gl/react-google-maps` se monta adentro de `MapPicker` (`:521`), solo cuando el mapa está
  disponible (`isMapAvailable`, `:294`: hay clave, hay conexión y Google no falló). Fuera de `MapPicker` no hay
  contexto de Maps, así que un formulario no puede usar `useMapsLibrary('geocoding')` por su cuenta.
- Si `value` cambia desde afuera, `MapPicker` mueve el pin y la cámara (`:266-287`).
- Ningún consumidor usa la Geocoding API hoy (`git grep -i geocod -- src` solo encuentra
  `geocodingResults: null` en un test de rutas).

## Propuesto

Tipos y helpers exportados nuevos en `src/ui/map.tsx`:

```typescript
/** CC-045: pedido de búsqueda. Cambiar `id` dispara una búsqueda nueva aunque `query` sea igual. */
export interface MapGeocodeRequest {
  readonly id: number;
  readonly query: string;
}

export type MapGeocodeOutcome =
  | { readonly status: 'found'; readonly coords: MapCoordinates; readonly approximate: boolean }
  | { readonly status: 'outside' }      // Google respondió, pero fuera de AGUILARES_BOUNDS
  | { readonly status: 'not_found' }    // ZERO_RESULTS
  | { readonly status: 'unavailable' }; // sin mapa (sin clave, sin conexión, Google caído) o error de la API

/** «dirección, barrio, Aguilares, Tucumán, Argentina», sin partes vacías. */
export function buildGeocodeQuery(address: string, zoneName?: string | null): string;

/**
 * Interpreta la respuesta del Geocoder. Toma el primer resultado; `approximate` es true si
 * `location_type` es APPROXIMATE, GEOMETRIC_CENTER o RANGE_INTERPOLATED, o si `partial_match` es true.
 * Sólo ROOFTOP sin `partial_match` se considera exacto. Coordenadas a 6 decimales.
 */
export function interpretGeocodeResponse(
  results: readonly GeocoderResultLike[] | null,
  status: string
): MapGeocodeOutcome;
```

Props opcionales nuevas de `MapPicker`:

```typescript
export interface MapPickerProps {
  // ... las de hoy, sin cambios
  /** CC-045: cada `id` nuevo busca `query` con la Geocoding API. */
  geocodeRequest?: MapGeocodeRequest | null;
  /** CC-045: resultado de cada búsqueda, con el pedido que la originó. */
  onGeocodeResult?: (outcome: MapGeocodeOutcome, request: MapGeocodeRequest) => void;
}
```

Comportamiento:
- Con el mapa disponible, un componente interno adentro del `APIProvider` usa `useMapsLibrary('geocoding')` y llama
  `geocoder.geocode({ address: query, componentRestrictions: { country: 'AR' }, bounds: { south: AGUILARES_BOUNDS.minLat, north: AGUILARES_BOUNDS.maxLat, west: AGUILARES_BOUNDS.minLng, east: AGUILARES_BOUNDS.maxLng } })`.
  **No pasar `AGUILARES_BOUNDS` directamente:** Google exige un `LatLngBoundsLiteral` con `south/north/west/east`;
  el `bounds` orienta resultados, no los restringe. Siempre validar el punto devuelto con `isWithinAguilaresBounds`.
- `found`: mueve el pin y la cámara como el GPS (`updateActiveCoords`, `requestCameraSync`), llama `onChange(coords)`
  y después `onGeocodeResult`. `outside`, `not_found` y `unavailable` no tocan el pin.
- Sin mapa disponible, un pedido nuevo responde `unavailable` enseguida: el formulario siempre recibe respuesta.
- Solo cuenta la última búsqueda: si llega la respuesta de un `id` viejo, se descarta.
- **No sobrescribir una corrección manual posterior al inicio de la consulta:** además del `id`, invalidar el resultado
  si durante la espera hubo click, drag, flechas de teclado, selección por GPS o cambio de coordenadas externo;
  comparar una revisión/época de selección capturada al iniciar. El botón explícito puede reemplazar un pin manual
  **solo si ese pin no volvió a editarse mientras la búsqueda estaba pendiente**. En descarte, no llamar `onChange`
  ni mostrar un aviso de resultado viejo; limpiar el estado pendiente del formulario tras la interacción manual.
- `query` vacía (después de `trim`) no consulta a Google; finalizar el pedido sin dejar al formulario esperando.
- En el modo Promise del Geocoder, capturar rechazos: `ZERO_RESULTS` se traduce a `not_found` y errores de API,
  importación de biblioteca o cuota a `unavailable`. Sin llamadas ni errores sin manejar.
- La consulta no se escribe en `console`, `notify`, analytics, URLs propias ni estado persistido.
- Sin `geocodeRequest`, `MapPicker` se comporta exactamente como hoy (consumidores actuales sin cambios).

## Seguridad y permisos

No aplica a esquema, RPC, RLS ni helpers de base: el cambio es solo de cliente. La clave sigue siendo la pública
`NEXT_PUBLIC_GOOGLE_MAPS_API_KEY`, restringida por HTTP referrer y, desde el 2026-11-05, a Maps JavaScript API,
Routes API y Geocoding API, con tope diario de la Geocoding API (Lautaro073). No hay clave de servidor ni Server
Action (D02=A de T-423). La CSP (`src/security/headers.ts`) ya permite `maps.googleapis.com`.

## Concurrencia e idempotencia

No aplica a la base. En el cliente: búsquedas seguidas se resuelven por `id` (gana la última) y una respuesta tardía
de un pedido viejo no mueve el pin.

## Compatibilidad, rollout y rollback

- **UI vieja contra el contrato nuevo:** las props son opcionales; sin ellas, `MapPicker` no cambia.
- **Esquema:** sin cambios.
- **Backfill:** no aplica; no se geocodifican direcciones guardadas.
- **Rollout:** este CC (documental) se mergea primero; T-423 implementa el contrato y lo usa en los formularios en
  una sola PR. **Antes de habilitar T-423 con datos reales**, resolver el aviso de privacidad versionado y la
  información al comercio/destinatario para el envío de direcciones a Google (issue #619).
- **Rollback:** revertir la PR de T-423 deja los formularios como hoy. Sin datos que migrar.
