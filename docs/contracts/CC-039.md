# CC-039 — RPC `get_publication_offer`: planes activos para el comercio

- **Issue:** #526 (label `contract-change`) · **Abre:** Lautaro073 (agente) · **Fecha:** 2026-10-22
- **Contrato afectado:** RPC nueva `public.get_publication_offer()` · `src/domain/rpc-contracts.ts` (entrada
  `get_publication_offer`) · `src/types/database.types.ts`
- **Tareas bloqueadas:** T-412 (#525)
- **Depende de:** CC-029 (créditos de publicación y catálogo), CC-038 (código del plan)

## Actual

- `publication_plans` tiene RLS sin policies para clientes y `revoke all` para `anon` y `authenticated`
  (`supabase/migrations/20261017090000_t369_publication_credits.sql`). Solo la lee el admin con
  `admin_list_publication_plans` (addendum D01-B de CC-029).
- El comercio ve su saldo y su plan con `get_my_publication_balance`, pero no tiene ninguna lectura del catálogo: en
  `/merchant/plan` no sabe qué planes hay ni sus precios de referencia, y el aviso de saldo agotado le dice que escriba
  para coordinar la compra.
- `platform_settings.loose_credit_reference_price_ars` (precio de referencia del crédito suelto, puede faltar) y
  `launch_discount_pct` (descuento de la primera compra) solo los lee el admin. El beneficio se consume con la primera
  compra registrada: queda una fila en `merchant_launch_discounts`, aunque el porcentaje sea 0.

## Propuesto

```sql
public.get_publication_offer() returns jsonb
```

```json
{
  "plans": [
    { "planId": "uuid", "name": "Plan 40", "kind": "quota", "monthlyCredits": 40, "referencePriceArs": 20000 },
    { "planId": "uuid", "name": "Ilimitado", "kind": "unlimited", "monthlyCredits": null, "referencePriceArs": null }
  ],
  "looseCreditReferencePriceArs": 900,
  "launchDiscountPct": 15
}
```

- **Quién:** el comercio con perfil `merchant`, consentimiento `active` y fila en `merchants`, con las mismas
  comprobaciones y errores que `get_my_publication_balance`: `UNAUTHENTICATED` sin sesión y `UNAUTHORIZED_ACTOR` para
  cualquier otro actor (repartidor, admin, comercio sin consentimiento o sin alta).
- **`plans`:** solo los planes `active = true`, ordenados por `sort, id`, hasta 50 (el catálogo es corto y curado por el
  admin; el tope protege la respuesta). Cada plan expone solo `planId`, `name`, `kind`, `monthlyCredits` y
  `referencePriceArs`: **no** devuelve `code`, `sort`, `active` ni timestamps.
- **`looseCreditReferencePriceArs`:** el valor de `loose_credit_reference_price_ars`, o `null` si no está cargado.
- **`launchDiscountPct`:** el `launch_discount_pct` vigente si es mayor que 0 **y** el comercio todavía no tiene fila
  en `merchant_launch_discounts`; si no, `null`.
- Es solo lectura (`stable`): no reconcilia, no reserva ni escribe.
- Errores: `UNAUTHENTICATED`, `UNAUTHORIZED_ACTOR` e `INTERNAL_ERROR` (un parámetro con un valor no entero, igual que
  `app_private.publication_setting_int`).

## Seguridad y permisos

- **RLS:** no cambia ninguna policy; `publication_plans`, `platform_settings` y `merchant_launch_discounts` siguen sin
  acceso directo nuevo para clientes.
- **Grants y revokes:** `revoke all on function public.get_publication_offer() from public, anon, authenticated;
  grant execute on function public.get_publication_offer() to authenticated`. La autorización real la hace la función.
- **`security definer`**, `stable`, `set search_path = public, pg_temp`. Corre como dueño para leer el catálogo, pero
  solo después de comprobar el actor.
- **Helpers internos:** reutiliza `app_private.publication_setting_int`; no agrega helpers.
- **Acceso directo frente a RPC:** la RPC no escribe.
- **Datos que nunca devuelve:** el código interno del plan, los planes inactivos, datos de otros comercios ni si otro
  comercio usó el descuento.

## Concurrencia e idempotencia

No aplica: es una lectura sin efectos. Un reintento devuelve el catálogo vigente.

## Compatibilidad, rollout y rollback

- **UI anterior contra el esquema nuevo:** la RPC es aditiva; la UI vieja no la usa.
- **Esquema anterior contra la UI nueva:** si la migración no está aplicada, la lectura falla y la sección muestra su
  estado de error sin romper el resto de `/merchant/plan`. La migración va en la misma PR y `migrate-*` corre antes de
  `deploy-*`.
- **Backfill:** no hace falta.
- **Rollout ordenado:** una sola PR (T-412).
- **Rollback:** `drop function public.get_publication_offer()`; ningún dato depende de ella.

## Decisiones de producto
