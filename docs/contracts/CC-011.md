# CC-011 — Contrato compartido de mapa src/ui/map.tsx, skeleton desacoplado y dependencia @vis.gl/react-google-maps

- **Issue:** #110 (label `contract-change`) · **Abre:** P2 (asako669) / revisión independiente PR #109 · **Fecha:** 2026-09-27
- **Contratos afectados:** `src/ui/map.tsx`, `src/ui/map-skeleton.tsx`, `package.json`, `pnpm-lock.yaml`
- **Tareas bloqueadas:** T-116 (#22, PR #109), futuras C06/R07 si consumen mapas

## Actual

No existe un componente compartido de mapa en `src/ui/` ni primitivas desacopladas para georreferenciación de locales/pedidos en Aguilares. La dependencia `@vis.gl/react-google-maps` no está instalada en `develop` (aunque fue preaprobada en `.agents/rules/25-stack-y-patrones.md`).

T-116 implementó inicialmente una versión en su rama, pero la revisión independiente (ronda 1 de PR #109) y la decisión D01 (1-A) de Lautaro073 exigieron detener la feature y extraer formalmente el contrato compartido a un `contract-change` previo y separado.

## Propuesto

### 1. Dependencia oficial
Fijar la dependencia oficial de Google Maps Platform para React:
- `@vis.gl/react-google-maps@1.10.1`

### 2. Separación de Skeleton para carga diferida (H03)
Crear `src/ui/map-skeleton.tsx` como módulo liviano independiente que:
- Solo importe `@/ui/skeleton` y utilidades de estilo del sistema de diseño.
- Tenga **cero** dependencias de `@vis.gl/react-google-maps` o del SDK de Google Maps.
- Permita a los formularios anfitriones (C01 `onboarding-form.tsx`, C03 `create-request-form.tsx`) utilizar `next/dynamic` con fallback visual sin arrastrar el SDK de mapas al bundle inicial de JavaScript (preservando el presupuesto First-Load JS < 180 kB).

### 3. Contrato público de `src/ui/map.tsx` (H01, H09)
Exportar:
- `MapCoordinates`: `{ lat: number; lng: number }`
- `AGUILARES_CENTER`: centro urbano (-27.4333, -65.6167)
- `AGUILARES_BOUNDS`: bounding box estricto (-27.4550 a -27.4100 lat, -65.6400 a -65.5950 lng)
- `aguilaresCoordinatesSchema`: esquema Zod de validación de coordenadas dentro de Aguilares
- `isWithinAguilaresBounds(lat, lng)`: función pura booleana de verificación
- `MapPickerProps`:
  ```ts
  export interface MapPickerProps {
    value?: MapCoordinates | null;
    onChange?: (coords: MapCoordinates) => void;
    defaultZoneCenter?: MapCoordinates | null;
    disabled?: boolean;
    className?: string;
    ariaLabel?: string;
    label?: string;
    helperText?: string;
    showLocationButton?: boolean;
    onLocationFound?: (coords: MapCoordinates) => void;
    onLocationError?: (error: string) => void;
  }
  ```
- Re-export de `MapSkeleton` desde `./map-skeleton`.

### 4. Responsabilidades de `MapPicker` (sin duplicación de controles - H09)
- **NO renderizar inputs de texto para dirección:** El formulario anfitrión (C01, C03) administra sus propios campos de dirección.
- **Botón GPS condicional (`showLocationButton`):** Opcional (por defecto desactivado si el anfitrión ya provee GPS, activable donde se requiera), evitando duplicación de acciones en C01 y C03.
- **Selector de pin interactivo:** Crosshair central fijo superpuesto (`data-testid="map-crosshair"`).
- **Callback real de arrastre (`onCameraChanged` - H06):** Captura `ev.detail.center` en cada cambio de cámara y notifica las coordenadas redondeadas a `onChange`.
- **D-pad de ajuste fino accesible:** 4 botones direccionales (Norte, Sur, Este, Oeste con paso de 0.0001° ~10m) con targets `>= 48px` (`min-h-12 min-w-12`), complementado con navegación por teclado (flechas) sobre el contenedor con foco visible.
- **Alerta inline de límites:** Advertencia con `role="alert"` si el pin se sitúa fuera del radio de Aguilares.

### 5. Fallback robusto ante fallos reales de Google Maps (H02)
- Detección de falta de API key o modo offline (`!navigator.onLine`).
- Detección de fallo real de carga del SDK o de inicialización mediante `APIProvider.onError` y `useApiLoadingStatus() === APILoadingStatus.FAILED`.
- En cualquiera de estos casos, degradación elegante mostrando aviso visible y garantizando que el flujo del formulario anfitrión continúe sin excepciones ni bloqueos.

### 6. Consumo estricto de variables de entorno públicas (H08)
- Consumo de `publicEnv.NEXT_PUBLIC_GOOGLE_MAPS_API_KEY` y `publicEnv.NEXT_PUBLIC_GOOGLE_MAPS_MAP_ID` desde `@/lib/env.public`, sin invocar `process.env` directamente en `map.tsx`.
