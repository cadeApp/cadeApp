## H17 — BLOQUEANTE ALTO — fetchNextPage durante refetch puede false-unlock
`request-offers-list.tsx` botón Cargar más llama `fetchNextPage()` con `disabled={isFetchingNextPage}`, sin bloquear `isFetching`, online ni sincronización. Durante el refetch de reconexión `isFetching=true`, `isFetchingNextPage=false` y el botón puede pulsarse. TanStack explica que `fetchNextPage` por defecto `cancelRefetch:true` puede cancelar el background refetch: https://tanstack.com/query/latest/docs/framework/react/guides/infinite-queries ; https://github.com/TanStack/query/issues/5972. Si nueva página termina, el latch H16 puede ver generación postreconexión, `fetchStatus='idle'`, `dataUpdatedAt` reciente y sin error, aunque las páginas previas sigan en caché sin actualizar. Esto pone en riesgo el no mostrar ofertas pending stale como aceptables.

**Evidencia:** inspección del código exacto SHA, verificación JS de expresiones y modelo Node independiente ejecutado; **NO** se reprodujo click real con React/TanStack porque no hay clon local accesible. Por ello la secuencia se consigna como riesgo sustentado que exige un test causal, no como explotación runtime confirmada. Acción: exponer isFetching del hook, deshabilitar y guardar handler Cargar más mientras fetching/offline/no-synced, test real con deferred multi-page y mutación RED.
