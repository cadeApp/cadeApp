## Origen

T-309 (PR #253) activó axe WCAG 2.2 A/AA en `/courier/onboarding/identity` y encontró `color-contrast` (serious)
preexistente en las tarjetas de carga de documentos. Corrida de referencia: `e2e-preview` run `37554952589`, test
`DoD: axe AA en onboarding`. El blob de `document-upload-card.tsx` es idéntico en `develop` y en la rama de T-309.

Elemento representativo: `<span class="text-sm font-semibold text-primary">Subir</span>`, con 2,39:1 sobre
`#ffffff` y 2,29:1 sobre `#f3fcfc`. Para texto de 14 px el mínimo es 4,5:1.

T-309 no amplía su alcance para arreglar esto.

## Análisis de estados (medido, 2026-10-08)

| Texto de 14 px | Estado | Color | Fondo | Contraste |
|---|---|---|---|---|
| «Subir» | idle | `text-primary` `#09BABD` | `#ffffff` / `#f3fcfc` | 2,39 / 2,29 ❌ |
| «Subir» con `text-primary-dark` | idle | `#0B7A7D` | `#ffffff` / `#f3fcfc` | 5,13 / 4,92 ✅ |
| asterisco de DNI obligatorio (`identity-form.tsx`) | — | `text-primary` | `#FDFCFB` | 2,34 ❌ |
| «Cargado» | success | `text-success` `#177A4B` | `#ffffff` | 5,35 ✅ |
| «Reintentar» | error | `text-destructive` `#C62828` | `#fcf4f4` | 5,19 ✅ |
| texto de estado | todos | `text-muted-foreground` `#5B6475` | `#ffffff` / `#f3fcfc` / `#fcf4f4` | 5,96 / 5,71 / 5,50 ✅ |

El ícono de carga (`RotateCw`) y los íconos con `text-primary` no son texto, así que `color-contrast` no los
evalúa. La tarjeta es compartida con el paso de vehículo (licencia y seguro), así que el arreglo cubre las dos
pantallas.

## Objetivo

Que `/courier/onboarding/identity` no tenga violaciones axe con los tags WCAG 2.0/2.1/2.2 A/AA que usa T-309, usando
el token existente `primary-dark`, sin cambiar el token global `primary` y sin silenciar reglas.

### Pruebas de componente por estado (PR306-H01)

En `src/features/courier-onboarding/components.test.tsx` se renderiza `DocumentUploadCard` en cada rama real:

| Caso | Props | Texto visible que se verifica |
|---|---|---|
| idle | `status="idle"` | título, texto de estado y «Subir» |
| uploading comprimiendo | `status="uploading"`, `compressing={true}` | título y texto de estado de compresión |
| uploading subiendo | `status="uploading"`, `compressing={false}` | título y texto de estado de subida |
| success | `status="success"`, `fileName="dni_front.png"` | título, `dni_front.png` y «Cargado» |
| error | `status="error"` | título, texto de error y «Reintentar» |

Para cada caso:

1. se verifica que se renderizan los elementos del estado (por texto o rol, no por clase);
2. se verifica el token específico de cada texto visible: «Subir» → `text-primary-dark`, «Cargado» →
   `text-success`, «Reintentar» → `text-destructive`, texto de estado → `text-muted-foreground`, título →
   `text-foreground`;
3. se verifica el contraste WCAG ≥ 4,5:1 de ese token sobre el fondo real del estado (`#ffffff`, `#f3fcfc` en hover
   idle y `#fcf4f4` en error), calculado con la fórmula de luminancia relativa de WCAG a partir de los valores de
   `src/ui/tokens.css`. Los valores esperados son los de «Análisis de estados».

Además, el asterisco de DNI de `IdentityForm` usa `text-primary-dark` con contraste ≥ 4,5:1 sobre `#FDFCFB`.

Una prueba cuya única aserción sea «no tiene `text-primary`» **no** cuenta como evidencia de contraste.

**RED conductual obligatorio:** con idle intacto, mutar provisionalmente el color de «Cargado» (`text-success`) y/o
de «Reintentar» (`text-destructive`) a `text-primary`. Tiene que fallar el test del estado afectado, por la
aserción de token o de contraste. Después se restaura el código y se muestra GREEN. Nunca se toca la expectation.
