## Diagnóstico

Los hooks vivos dependen de Postgres Changes sobre:
- `public.offers`
- `public.delivery_requests`

Consumidores:
- `useRequestOffers` → `offers`
- `useAvailableRequests` → `delivery_requests` + `offers`
- `useTrip` → `delivery_requests`

El barrido de todas las migraciones actuales de `develop` no encuentra:
- `ALTER PUBLICATION supabase_realtime ...`
- `pg_publication_tables`
- alta versionada de `offers` o `delivery_requests` en la publicación

`supabase/config.toml` tampoco declara/configura esta pertenencia.

La política RLS necesaria para el caso T-307 sí existe (`offers_select_merchant`). Por lo tanto, el defecto de raíz es la falta de inclusión de las tablas en la publicación `supabase_realtime` de Postgres en los entornos gestionados por migraciones.

## Decisiones

- **Migración idempotente y declarativa:** Se agrega un bloque PL/pgSQL que comprueba `pg_publication_tables` y ejecuta `alter publication supabase_realtime add table public.offers;` y `alter publication supabase_realtime add table public.delivery_requests;` únicamente si no están presentes.
- **Sin drop ni recreate:** No se altera ni recrea la publicación `supabase_realtime` para no interferir con otras tablas configuradas por el motor o extensiones.
- **Sin REPLICA IDENTITY FULL innecesario:** No se altera la identidad de réplica salvo necesidad demostrada; T-307 solo necesita eventos INSERT.
- **Fail-closed DB test (pgTAP):** Se añade `supabase/tests/t335_realtime_publication.sql` que verifica que ambas tablas pertenezcan a `supabase_realtime` en `pg_publication_tables`. Si falta cualquiera de las dos, el test falla (RED).
