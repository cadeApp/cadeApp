- **Diagnóstico browser-level y clasificación (Caso A confirmado):**
  - **Secuencia analizada:**
    1. Usuario inicia sesión como repartidor (`/courier/feed`).
    2. Las cookies de Supabase Auth (`sb-*`) quedan registradas en el navegador.
    3. Navegación a ruta 404 inexistente (`/t336-404-session-regression`) dentro del mismo BrowserContext: las cookies permanecen intactas (se descarta Caso B: pérdida/rotación de cookies).
    4. Al pulsar «Ir al inicio», los componentes utilizaban `<Link href="/login">` de `next/link`. En Next.js App Router, `<Link>` ejecuta navegación de cliente (soft navigation). Como `/login` ya había sido visitado y cacheado en el Client Router Cache en estado anónimo previo a la autenticación, el enrutador de cliente reutilizaba la vista cacheada sin forzar el roundtrip documental HTTP necesario para que `middleware.ts` intercepte la navegación.
    5. Por el contrario, una navegación de documento forzada (hard navigation) hacia `/login` emite una petición HTTP GET que llega a `middleware.ts`. El middleware ejecuta `updateSession()`, lee las cookies presentes, evalúa `evaluateRouteGuard('/login', session)` y emite un HTTP 307 Redirect hacia el home canónico del repartidor (`/courier/feed`).
    6. Se descarta el Caso C (fallo en `updateSession`), confirmando categóricamente el **Caso A: bug de navegación cliente / client router cache del gateway**.
