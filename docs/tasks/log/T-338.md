## Sesión 2026-10-08 06:15 — Resolución PR295-R01 (First Load JS <= 180 kB) y Preservación de DoD

- **Objetivo:** Resolver el hallazgo bloqueante PR295-R01 (Decisión P1 1-A): reducir el First Load JS en `/`, `/legal`, `/login` y `/register` a `<= 180 kB` cada una, conservando la API canónica `@/features/notifications` (Decisión P1 0-A), sin deep imports desde `src/app/**`, sin romper SSR ni hidratación, y asegurando suite completa en verde.
- **Causa raíz diagnosticada e inspeccionada en los chunks de producción:**
  1. En Next.js App Router (RSC), `src/features/notifications/index.ts` es un módulo evaluado en el servidor. Al ser importado por Server Components (`HomePage`, `LoginPage`, `RegisterPage`, `LegalIndexPage`), el extractor de referencias de cliente RSC recorría el grafo de exports e imports dinámicos del barrel.
  2. Las exportaciones estáticas directas de `PushPermissionPrompt` y `push/subscription` registraban referencias cliente que incorporaban `zod` (56 kB) y `lucide-react` (25 kB) en el manifest de cada una de las cuatro rutas públicas.
  3. `loadIosInstallGuideSheet` como dynamic import de cadena estática dentro de un módulo servidor provocaba que Next.js registrara `ios-install-guide-sheet.tsx` como Client Reference, arrastrando `framer-motion` (116 kB) y `@radix-ui/react-dialog` (38 kB) a través de `src/ui/sheet.tsx`.
- **Implementación y desacoplamiento arquitectónico:**
  1. `src/features/notifications/index.ts`:
     - `PushPermissionPrompt` desacoplado mediante `React.lazy` envuelto en `React.Suspense` con chunk dedicado (`webpackChunkName: "push-prompt"`).
     - Helpers de suscripción push (`requestNotificationPermission`, `subscribeToPush`, `unsubscribeFromPush`, `getPushSubscription`) convertidos a funciones asíncronas con dynamic import tipado exactamente (`typeof import('./push/subscription')...`).
     - `loadIosInstallGuideSheet` desacoplado a través del boundary cliente aislado de `standalone-redirect.tsx`, evitando la inclusión de `Sheet`/`motion`/`dialog` en el flight manifest del servidor.
  2. `src/features/notifications/install/index.ts`:
     - Marcado explícito `'use client'` que establece la frontera cliente del submódulo.
     - Conservación de todos los exports públicos existentes (incluido `ios-install-guide-sheet` para compatibilidad con suites como `visual-verification.test.tsx`).
  3. `src/features/notifications/install/standalone-redirect.tsx`:
     - Aloja `loadIosInstallGuideSheet` dentro de la frontera cliente.
  4. Páginas públicas (`src/app/page.tsx`, `login/page.tsx`, `register/page.tsx`, `legal/page.tsx`):
     - Mantienen import canónico estricto desde `@/features/notifications` (Decisión 0-A), sin imports profundos.
