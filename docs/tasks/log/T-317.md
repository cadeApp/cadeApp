## 2026-09-30 — Lautaro073 (Claude Code) · PR139-H13 (formato real del QR)
- **Origen:** la prueba real en `cadeapp-staging`, corrida por Lautaro073, pasó login, rol admin y `mfa.enroll()`, y cortó con «Supabase devolvió el QR en un formato inesperado. No se escribió ningún archivo.». `git pull` dejó la rama en `8b347e4` (Ronda 4); sin rebase, amend ni force.
- **Causa:** `qrSvgFromDataUri()` corría `decodeURIComponent` sobre el cuerpo y exigía que empezara con `<svg`. En `@supabase/auth-js@2.116.0` (`GoTrueClient.js`), `qr_code` es `` `data:image/svg+xml;utf-8,${data.totp.qr_code}` ``: el SVG va crudo, sin codificar. Supabase Auth lo genera con SVGo, que antepone una declaración XML y un comentario a la raíz `<svg`. El fixture `QR_UTF8` de los tests armaba la data URL con `encodeURIComponent(SVG)`, un contrato que no es el real; por eso las pruebas no lo detectaron.
- **Hecho:**
  - `tools/admin-mfa-enroll.mjs`: sigue exigiendo el prefijo exacto, quita solo ese prefijo, ya no decodifica y valida el cuerpo con `SVG_DOCUMENT`: espacios, declaración XML y comentarios opcionales, raíz `<svg` seguida de espacio o `>`, y fin en `</svg>`. Devuelve el XML tal como vino. No se agregó ningún fallback ni salida del secreto, `qr_code`, `totp.uri`, contraseña, código o tokens.
  - `tools/admin-mfa-enroll.test.ts`:
    - `QR_UTF8` pasa a modelar el contrato real (SVG crudo tras el prefijo);
    - fixture nuevo `REAL_SUPABASE_QR` con la forma de SVGo (declaración XML + comentario + `<svg>`);
    - tests nuevos:
      - `qrSvgFromDataUri` conserva declaración, comentario y raíz;
      - `enrollAdminMfa` con el QR real llega a `{ ok: true }` y `writeQr` recibe el XML completo, no la data URL;
      - prefijo `data:text/plain,` → error;
      - `<?xml …?>not-svg` → error.
    - Se mantienen SVG crudo, base64 y `not-svg` → error.
  - `docs/tasks/T-317.md`: el caso de prueba del QR ya no dice que el archivo «empieza con `<svg`». Ahora dice que es el XML SVG tal como vino tras el prefijo exacto, que puede llevar declaración y comentarios, y que contiene una raíz `<svg` válida.
