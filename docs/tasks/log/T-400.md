- **Decisiones y por qué:**
  - Si una consulta de nombres falla, la página no falla: esa entidad queda con su id corto. Los nombres son un
    agregado de lectura y la auditoría tiene que poder leerse igual; el error de `audit_log` sí se sigue propagando.
  - Los ids se validan como uuid antes del `in(...)`: un `target_id` que no lo sea no tira abajo la consulta de los
    demás.
  - Repartidores y dueños de documentos comparten una sola consulta a `profiles` (menos que «una por tipo»).
  - Un mismo valor en los dos lados (por ejemplo `kind` en `add_courier_optional_document`) se muestra una vez: también
    se leía como un cambio.
  - El test de `getAuditLog` de T-123 que exigía que no apareciera «30111222» se ajustó: ese texto es el motivo de
    `admin_decide_courier`, que ahora se muestra por la decisión de Lautaro073 (2026-10-21). Sigue exigiendo que no
    aparezcan las notas libres de `admin_set_subscription`.

    se dejó como estaba para no inflar el diff.
