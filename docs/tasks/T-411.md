## Objetivo

El formulario «Nuevo plan» del admin pide un «Código» técnico (minúsculas, guiones) que el admin tiene que inventar.
Con esta tarea el código lo genera la base desde el nombre, único y fijo, y el formulario deja de pedirlo.

## Reconciliación de contratos

CC-038 (#518) cambia la semántica de `admin_upsert_publication_plan` sin cambiar su firma y saca `code` del input del
dominio; esta ficha cubre cada archivo, suite y prueba de su «Impacto exacto en la tarea».

## Regla de pruebas
La evidencia RED tiene que fallar por el comportamiento real que falta. Está prohibido fabricar RED o GREEN:
- comentando código;
- adulterando expectations;
- agregando ramas `if (test)`;
- usando mocks que eviten el camino de producción;
- debilitando una aserción solo para que pase CI.

Una **mutación** que rompe a propósito la regla para demostrar que el test la protege es válida si es local,
temporal, restaurada y sin commit. Si hace falta evidencia de CI (pgTAP o multisesión), se usa una rama y PR aislada
`review/T-411-<mutacion>` marcada **`REVIEW ONLY / NEVER MERGE`**, que se cierra sin mergear.
