# T-203 — Emisor base de push

- **Zona / dueño:** P1 · **Issue:** #30 · **Fase:** Fase 2 (PWA, notificaciones y accesibilidad)
- **Dependencias (mergeadas en develop):** T-103
- **Contratos a leer:** `src/domain/**`, `AGENTS.md`, `.agents/rules/**`
- **Tarea dependiente de integración:** T-206 (#92)

## Objetivo
Proveer el servicio base server-side de Web Push del fallo del Juez de `revision-1`: almacenamiento/gestión de suscripciones, validación de payload, transporte VAPID y política de entrega/limpieza.

**T-203 no cablea el emisor dentro de las transiciones de negocio.** Ese trabajo se realiza en T-206, que depende de T-203.

## Responsabilidades de T-203
- Almacén y API server-side para alta/baja de suscripciones por usuario/dispositivo, con acceso dueño-solo y lectura para envío solo desde servidor.
- Conservar los metadatos necesarios del dispositivo, incluida `platform`, cuando correspondan al contrato de suscripción.
- Emisor Web Push con runtime Node y VAPID; la clave privada queda solo del lado servidor.
- Payload mínimo validado estrictamente: tipo de evento e IDs necesarios, sin teléfono, dirección, DNI, selfie ni otros datos personales.
- Tratar 404/410 como suscripción inválida/expirada y eliminarla; 429/5xx y otros errores transitorios no deben destruir suscripciones válidas.
- Exponer resultado/código de respuesta por intento (o representación equivalente auditable) para que el call site pueda observar el despacho.
- Proveer una envoltura best-effort para que una falla del emisor no se propague como fallo de la transición que lo invoque.

## Fuera de alcance
- Invocar push desde `publish_request`, `submit_offer`, `accept_offer`, cancelaciones, expiraciones u otras transiciones de negocio.
- Cablear purgas desde logout o desde la suspensión/deshabilitación de un repartidor.
- Modificar los call sites de negocio (`src/server/rpc/**`, `src/server/cron/**`, actions/features) para enviar o purgar push.
- Modificación de archivos no autorizados en la lista anterior.
- Cambios de contratos sin procedimiento `contract-change`.

Los tres primeros puntos quedan asignados a **T-206 (#92)**. T-203 puede cerrarse como servicio base sin afirmar que el flujo end-to-end de notificaciones ya está cableado.
