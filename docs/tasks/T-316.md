- **Contratos a leer:** `AGENTS.md`, `.agents/rules/**`, `vercel.json`, `src/app/api/cron/health/route.ts`

## Objetivo
Vercel rechaza el deploy de staging (run `deploy` 36543241685) porque el plan Hobby solo admite crons diarios y
`vercel.json` programa `/api/cron/health` cada 10 minutos (T-310). Decisión de Lautaro073 (opción 1): el chequeo de
uptime se mueve a un workflow programado de GitHub Actions que llama a `/api/cron/health` con `CRON_SECRET`, y
`vercel.json` queda solo con crons diarios. El endpoint y su lógica no cambian.

## Notas para quien retome
- Los `schedule` de GitHub Actions corren desde la rama por defecto (`develop`) y pueden atrasarse algunos minutos:
  alcanza para un chequeo de uptime; el push sigue sin ser la única señal de nada.
- `/api/cron/health` sigue en el código y sigue exigiendo `CRON_SECRET`; solo cambia quién lo invoca.
- Producción necesita `PRODUCTION_APP_URL` y `CRON_SECRET` en el environment `production`.
