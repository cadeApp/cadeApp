# T-432 — SEC-07: suscripciones push solo por RPC, allowlist de servicios push y timeout

- **Zona / dueño:** P1 · **Issue:** #665 · **Fase:** Fase 4 (Admin después del lanzamiento)
- **Dependencias (mergeadas en develop):** T-409, T-386 (CC-035), CC-040, T-408 (CC-047), CC-049
- **Contratos a leer:** `docs/contracts/CC-049.md`; RPC `register_push_subscription`; policies de
  `push_subscriptions`; `src/domain/rpc-contracts.ts` (`registerPushSubscriptionInputSchema`); `src/server/push/sender.ts`.

## Objetivo

Cierra **SEC-07** de la revisión de seguridad de T-312. Hoy un usuario puede escribir por REST una suscripción con un
endpoint arbitrario y el servidor le hace POST (SSRF ciego), sin timeout. Después de esta tarea la única escritura es
la RPC, que solo acepta los servicios push de los navegadores. El emisor descarta cualquier otro host y corta cada
envío a los 5 s.

## Regla de pruebas

La evidencia RED tiene que fallar por el comportamiento real que falta. Está prohibido fabricar RED o GREEN:
- comentando código;
- adulterando expectations;
- agregando ramas `if (test)`;
- usando mocks que eviten el camino de producción;
- debilitando una aserción solo para que pase CI.

Una **mutación** que rompe a propósito la regla para demostrar que el test la protege es válida, con estas condiciones:

- **Preferido:** una mutación local temporal, restaurada y sin commit, si con eso alcanza. Se describe en la bitácora
  con la mutación exacta y las líneas resumen de RED y GREEN.
- **Si hace falta evidencia de CI** (por ejemplo `pnpm test:db`, que no corre en local):
  - se usa una rama y PR **aislada** `review/T-432-<mutacion>`, marcada en el título y en el cuerpo como
    **`REVIEW ONLY / NEVER MERGE`**;
  - el commit mutado nunca se mezcla con la rama de la tarea;
  - se registran en la bitácora el SHA mutado y el run de CI como evidencia;
  - después de capturar la evidencia, la PR de mutación se cierra sin mergear;
  - la rama real queda con el código correcto.

- adulterar tests o debilitar expectations;
