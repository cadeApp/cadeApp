## Origen

T-328 nació como **excepción issue-first** durante la revisión independiente de T-306 / PR #198.

La revisión detectó que `createDeliveryRequestAction` creaba una solicitud en `draft`, guardaba el contacto y devolvía éxito sin invocar `publish_request`, mientras la UI mostraba «Solicitud publicada con éxito». Se abrió primero el issue #209 para desbloquear T-306. Lautaro073 autorizó regularizar ese bug como T-328 después de que la implementación ya existía en la rama `fix/209-publish-request-on-create`.

No se reescribe historia ni se fabrica una bitácora retroactiva: la trazabilidad previa queda en el issue #209, commits `3fb71a7` y `102202d`, cuerpo de PR #210 y la nota de regularización de `docs/tasks/log/T-328.md`.

## Objetivo

El alta productiva de una solicitud debe invocar la RPC `publish_request` para la fila recién creada. La autorización final de `draft -> published` queda exclusivamente en la RPC/DB. La action solo devuelve `ok` si la RPC devuelve una publicación válida; si rechaza, propaga el código de dominio y la UI no anuncia éxito.

## Residual conocido

Si `publish_request` rechaza, la solicitud y su contacto quedan persistidos en `draft`. Evitarlo correctamente requiere una operación atómica de creación + publicación y, por tanto, un cambio de contrato separado. Lautaro073 decidió que ese residual no forma parte de T-328.
