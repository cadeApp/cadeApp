# T-374 — Timeout del gate E2E de staging para la suite completa

- **Zona / dueño:** P1 · **Issue:** #428 · **Fase:** calidad / operación previa al release
- **Dependencias (mergeadas en develop):** T-315, T-331
- **Contratos a leer:** `AGENTS.md`, `.agents/rules/40-testing.md`, `.agents/rules/50-git-y-coordinacion.md`, `.github/workflows/e2e-staging.yml`, `.github/workflows/deploy.yml`, `.github/workflows/verify-workflows.test.mjs`, `playwright.config.ts`

## Problema verificado

El job `e2e-staging` tiene `timeout-minutes: 20`. La corrida real [39006925376](https://github.com/cadeApp/cadeApp/actions/runs/39006925376) completó **82 tests Chromium en 18,3 minutos** sobre el árbol anterior; las pruebas incorporadas después aumentaron el tamaño de la suite (T-369, T-373, etc.). Un timeout tan ajustado puede terminar un gate correcto antes de que finalice.

La [PR #427](https://github.com/cadeApp/cadeApp/pull/427) ya propuso el cambio funcional `20 → 45`, pero su revisión [PR427-H01](https://github.com/cadeApp/cadeApp/pull/427) detectó un desvío de alcance: la ficha histórica T-315 autoriza `deploy.yml`, **no** `e2e-staging.yml`. Esta T-374 autoriza el mantenimiento del job E2E sin reabrir o alterar retrospectivamente T-315 ni rehacer el cambio funcional en otra PR.

## Objetivo

Ampliar a **45 minutos** el presupuesto máximo del job `e2e-staging` preservando el gate completo, sin omitir ninguna prueba ni alterar su semántica. El cambio no afecta el comportamiento de producto, migraciones, el orden de deploy ni los entornos.

## Regla de pruebas

Prohibido fabricar RED/GREEN, omitir pruebas o modificar un test para que pase. Si un gate falla por motivo ajeno, diagnosticar y reportar; no silenciar.
