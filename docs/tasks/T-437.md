## Objetivo

Cierra **B-05** de la revisión de seguridad de T-312. Hoy un admin con MFA puede aprobar o rehabilitar a un
repartidor cuyo DNI, selfie o foto de perfil nunca se verificó, o fue rechazado. Después de esta tarea:
- las dos RPC exigen los cuatro documentos obligatorios del alta vigentes, verificados y sin purgar;
- la UI del admin lo refleja;
- un `rejected` o `suspended` puede volver a cargar un obligatorio para que el admin lo verifique, sin
  rehabilitarse solo.

## Regla de pruebas

La evidencia RED tiene que fallar por el comportamiento real que falta. Está prohibido fabricar RED o GREEN:
- comentando código;
- adulterando expectations;
- agregando ramas `if (test)`;
- usando mocks que eviten el camino de producción;
- debilitando una aserción solo para que pase CI.

Adaptar un fixture para que siembre documentos verificados no es debilitar una aserción: refleja la regla nueva. Cada
suite adaptada conserva todas sus expectativas.
