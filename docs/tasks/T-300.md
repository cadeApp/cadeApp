# T-300 — Promoción inicial `develop → staging`

- **Zona / dueño:** P1 · **Issue:** #96 · **Fase:** Fase 3 (Calidad, operación y salida)
- **Dependencias (mergeadas en develop):** T-003, Fase 1
- **Contratos a leer:** `AGENTS.md`, `.agents/rules/**`, `.github/workflows/migrate.yml`

## Objetivo
Checkpoint operativo obligatorio antes de T-301: promover un `develop` verde a `staging`, permitir que el workflow oficial aplique las migraciones acumuladas sobre `cadeapp-staging` y verificar que el deployment de staging esté sano antes de comenzar los E2E.

## Archivos permitidos
- `docs/tasks/T-300.md`
- `docs/tasks/log/T-300.md`
- `docs/revision-pr/**`

## Fuera de alcance
- Aplicar migraciones manualmente desde una laptop
- Usar o modificar producción
- Cambiar código de producto para “hacer pasar” el checkpoint
- Copiar secretos, contraseñas, connection strings o webhooks al repo/issue/log

## Dependencias nuevas permitidas
- ninguna

## DoD
- [ ] `develop` está verde y se promueve mediante PR `develop → staging`; el PR de promoción no incorpora cambios de feature ni resuelve conflictos agregando código.
- [ ] El merge/push a `staging` dispara `.github/workflows/migrate.yml` y el job `migrate-staging` termina verde.
- [ ] Las migraciones se aplican únicamente desde GitHub Actions mediante `pnpm supabase db push --yes` sobre el environment `staging`.
- [ ] La verificación de drift de `src/types/database.types.ts` contra staging termina verde.
- [ ] El deployment correspondiente a la rama `staging` queda accesible.
- [ ] `/api/health` del deployment de staging responde HTTP 200.
- [ ] La bitácora registra el SHA de `develop` promovido, el SHA resultante de `staging` y referencias no secretas a los runs/deployment.
- [ ] Solo después de cumplir todo lo anterior se cierra el Issue #96; ese cierre es el evento que permite a `board-sync` desbloquear T-301.

## Notas para quien retome
- Este checkpoint existe para que T-301 nunca empiece contra un staging viejo o sin migraciones.
- `board-sync` considera T-300 completada cuando su issue queda cerrado; **no cerrar #96 antes de verificar migrate-staging, deployment y health**.
- La promoción inicial no reemplaza promociones posteriores: nuevas migraciones/features que necesiten E2E deben volver a pasar de `develop` a `staging` antes de probarse allí.
- Producción no participa de T-300.
