# T-317 — Alta de admin y enrolamiento del primer factor MFA

- **Zona / dueño:** P1 · **Issue:** #137 · **Fase:** Fase 3 (Calidad, operación y salida)
- **Dependencias (mergeadas en develop):** T-004, T-122, T-300
- **Contratos a leer:** `AGENTS.md`, `.agents/rules/**`, `docs/master-plan.md` §9.3 (Admin), `docs/tasks/T-004.md` (procedimiento de arranque `PR54-H03`), `src/features/admin/actions.ts` (`verifyAdminMfaAction`, `requireAdminAal2`), `app_private.assert_admin_aal2`

## Objetivo
Hoy no hay forma de tener un admin operativo. El rol `admin` se asigna solo por SQL (master plan §9.3), pero el procedimiento de T-004 («para T-005») nunca llegó a un runbook. Además, ninguna tarea enrola el primer factor TOTP: T-122 solo verifica un factor que da por existente, y sin factor `verifyAdminMfaAction` devuelve `INTERNAL_ERROR`. Esta tarea cierra el recorrido completo: promover la cuenta → enrolar el TOTP → entrar con `aal2` → operar.

Decisión de Lautaro073 (2026-09-30): el primer enrolamiento lo hace el operador con una herramienta local de un solo uso (`tools/`), **no** una pantalla de la app. Una pantalla de enrolamiento abierta a cualquier admin sin factor dejaría llegar a `aal2` a quien tenga solo la contraseña.

### Ambiente y excepción operativa
develop y staging comparten el proyecto remoto `cadeapp-staging` (decisión D01 / 1-B; `docs/master-plan.md` §12). T-317 trabaja contra ese proyecto compartido. La excepción operativa de esta tarea permite **solo**:
- `NEXT_PUBLIC_SUPABASE_URL`;
- `NEXT_PUBLIC_SUPABASE_ANON_KEY`;
- el email y la contraseña del usuario final admin, ingresados de forma interactiva y mantenidos solo en memoria.

Siguen prohibidos: `SUPABASE_SERVICE_ROLE_KEY`, la contraseña o URL de la base, access tokens de infraestructura (Supabase, Vercel, GitHub), `supabase link`, `supabase db push` y cualquier otro secreto privilegiado.

### Excepción de alcance web (Ronda 7, PR #139)
Decisión de Lautaro073 (2026-09-30): la segunda corrida en `cadeapp-staging` llegó al flujo web y expuso dos defectos (PR139-H14 y PR139-H15) que impiden cerrar el recorrido `/login` → `/login/mfa` → `/admin/applicants`. Se autoriza corregirlos dentro de T-317 tocando **solo** los archivos de auth/admin listados en «Archivos permitidos» bajo esta excepción. No se amplía a `src/**`, no se agregan códigos de dominio y no se tocan DB, RLS, RPC ni la herramienta CLI.
- **H14:** un login de admin sin `redirectTo` terminaba en `/`. Debe terminar en `/login/mfa?redirectTo=%2Fadmin%2Fapplicants` y, tras el MFA, en `/admin/applicants`, con el destino derivado del guard existente y sin open redirect.
- **H15:** `verifyAdminMfaAction` devolvía `INTERNAL_ERROR` tanto si fallaba `listFactors` como si no había un TOTP verificado. Lista válida sin TOTP verificado → `AAL2_REQUIRED` (código existente) con un mensaje específico en la pantalla MFA; los errores de `listFactors` y de `challenge` → `INTERNAL_ERROR`; código incorrecto → `VALIDATION_ERROR`.
