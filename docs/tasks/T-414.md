## Objetivo

El admin no tiene cómo avisar promociones o novedades. Con esta tarea, una sección «Novedades» del admin envía un
aviso a comercios, repartidores o ambos: llega por push a quien aceptó novedades al activar las notificaciones y queda
como banner en la home del comercio (`/merchant/dashboard`) y del repartidor (`/courier/feed`), con cierre por cuenta y
el enlace «No recibir más promociones».

## Reconciliación de contratos

CC-040 (#539) agrega las tablas, las RPC y el evento push `announcement`; esta ficha cubre cada archivo, suite y prueba
de su «Impacto exacto en la tarea».

## Regla de pruebas
La evidencia RED tiene que fallar por el comportamiento real que falta. Está prohibido fabricar RED o GREEN:
- comentando código;
- adulterando expectations;
- agregando ramas `if (test)`;
- usando mocks que eviten el camino de producción;
- debilitando una aserción solo para que pase CI.

Una **mutación** que rompe a propósito la regla para demostrar que el test la protege es válida si es local,
temporal, restaurada y sin commit. Si hace falta evidencia de CI (pgTAP), se usa una rama y PR aislada
`review/T-414-<mutacion>` marcada **`REVIEW ONLY / NEVER MERGE`**, que se cierra sin mergear.

## Notas para quien retome

- Los textos de la novedad los escribe el admin: van como texto plano (React escapa) y nunca se usan como URL; la URL
  del push sale del mapa fijo del servidor.
- El banner es la vía dentro de la app que exige la regla «el push nunca es la única forma de enterarse».
