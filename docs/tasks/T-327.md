# T-327 — E2E de Preview por PR con Vercel + Supabase Develop

- **Zona / dueño:** P1 · **Issue:** #205 · **Fase:** Fase 3 (Calidad, operación y salida)
- **Dependencias (mergeadas en develop):** T-301, T-315
- **Contratos a leer:** `AGENTS.md`, `.agents/rules/**`, `e2e/AGENTS.md`, `.github/workflows/{migrate,deploy,e2e-staging}.yml`, `playwright.config.ts`

## Objetivo
Validar las PR internas directamente contra su Vercel Preview antes de mergear a `develop`, usando el Supabase
Develop compartido. Staging deja de ser el entorno de iteración por PR y queda reservado para checkpoints y
release candidates. T-303 (#35) y #200 no son dependencias: esta tarea existe para que sus arreglos se puedan
probar en Preview sin promociones repetidas a staging.

Decisiones P1 (issue #205, 2026-10-02):
- Las PR internas se validan directamente contra su Vercel Preview usando Supabase Develop compartido.
- Vercel despliega develop/previews mediante Git Integration; GitHub Actions no despliega Vercel Develop.
- Las PR con migraciones no aplican schema remotamente a Supabase Develop antes del merge.
- 1-A: Vercel Authentication se desactiva a mano solo para Preview en `cadeApp-develop`; sin bypass secret.
- 2-A: variable no secreta `SUPABASE_DEVELOP_PROJECT_REF` en el Environment `develop`.
- 3-A: el merge de esta infraestructura no cierra #205; sigue abierta hasta una corrida real `e2e-preview` GREEN.
- 4: el Project ID de Vercel es el Environment secret `VERCEL_PROJECT_ID`.
- 5-A: se acepta el límite nativo de `concurrency` de GitHub; sin cola FIFO propia.
- 6-A: se actualizan `AGENTS.md`, `.agents/rules/00-confianza-y-seguridad.md` y `e2e/AGENTS.md` solo para reflejar
  el Supabase Develop separado.

Esta ficha nació con la rama de implementación (excepción issue-first decidida por P1 en #205): no existía en
`develop` antes de la PR #206.

## DoD
